## 1. 账号隔离原则（先看这条，再看具体步骤）

`docs/SkillsBin-开发文档.md` §10.0 的额度账，结论是分开的必要性"一半一半"：

| 资源 | 计费口径 | 共用同账号的后果 | 结论 |
|---|---|---|---|
| GitHub REST API | **每个 PAT 5000 次/时**（代码搜索独立：10 次/分） | 两站都用满一轮就会互相抢额度 | ✅ **必须分开**（额度按 token 分桶，硬收益） |
| GitHub Actions 分钟 | **每个账号**：私库 2000 min/月，**公开库不限量** | GetHub 私库已顶满 2100 min/月 → 共用必超 | ✅ **必须分开**；且新站走 public 直接免掉这个额度 |
| Cloudflare Pages 构建 | **每个账号 500 次/月** | 两站合计约 120~180 次，远未触限 | ⬜ 共用也够 |
| CF 带宽 / 请求 / 站点数 | 不限 | 无消耗 | ⬜ 共用也够 |

**所以：GitHub 新账号是硬需求；Cloudflare 新账号的收益是「凭据独立、审计独立、将来能把 SkillsBin 当作独立资产整体转手」，不是省额度。**

⚠️ **反向提醒**：Cloudflare 对「短时间内大量创建项目」有防滥用机制，可能临时禁用新建项目权限。**不要为了突破免费额度批量开小号** —— 一个账号服务一个站点是完全正常的用法。

⚠️ **凭据一律不许复用 GetHub 的**。代码、脚本、数据结构可以整份搬，`GITHUB_TOKEN` / `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` **必须新建**。

## 2. 逐项申请指南

### 2.1 新 GitHub 账号

1. 注册 → 完成**邮箱验证**（不验证无法跑 Actions）。
2. 开启 **2FA**（Settings → Password and authentication）—— 新账号不做风控容易被标记。
3. 记下用户名，填进 `.deploy.env` 的 `GH_OWNER`。

> **爬坡建议（写进文档 §10.0.3）**：新账号立刻以 5000 次/小时 的强度抓取容易被风控。**前 2~3 天我会先用 `--limit 50` 小流量跑**，确认无异常再放开定时任务。

### 2.2 新建仓库 `SkillsBin`

- 可见性选 **public**（`GH_VISIBILITY=public`）。
- 可以先不初始化 README / .gitignore / license —— 首次推送时我会带上。

**为什么是 public（文档 §10.0.2 的取舍表）**

| 维度 | public | private |
|---|---|---|
| Actions 分钟 | **不限量（免费）** | 2000 min/月，采集两班倒就会超 |
| 投稿 PR | 所有 GitHub 用户都能提，**无需邮件兜底** | 外部访客提 PR 跳 404，必须降级为邮件提交 |
| 数据资产 | 公开可见 —— 但本站数据本身就是公开的 GitHub 元数据，保密价值基本为零 | 不公开 |
| 密钥安全 | 全走仓库 Secrets；`.deploy.env` 绝不入库（**此规则与可见性无关，始终生效**） | 同 |

### 2.3 仓库级两个开关（不设会**静默失败**，GetHub 踩过）

仓库 → **Settings → Actions → General**：

- [ ] **Workflow permissions** → 选 **Read and write**
- [ ] 勾上 **Allow GitHub Actions to create and approve pull requests**

不设的后果：**数据提交被拒**、**审核 PR 建不出来** —— 而且失败现象很不直观。

> 我已经在 PAT 里要了 `Administration: Read and write`，所以**这两个开关我可以用 API 帮你设**（`PUT /repos/{owner}/{repo}/actions/permissions/workflow`）。你自己点也就 1 分钟，随你。

### 2.4 GitHub fine-grained PAT（Repository access 1 步 + Permissions 加 5 项）

**路径**：github.com → 右上头像 → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token

| 项 | 填什么 |
|---|---|
| Token name | `skillsbin-dev` |
| Expiration | **90 days**（到期我会提醒你轮换） |
| Resource owner | **新账号** |

**Repository access**（界面三个单选，选第三个）：

| 界面选项 | 含义 | 选不选 |
|---|---|---|
| ⚪ Public repositories | 只有公共仓库、且只读 —— **不能写你自己的仓库**，推不了代码 | ❌ |
| ⚪ All repositories | 账号下现在+将来全部仓库都授权，权限偏大 | 不必要 |
| ✅ **Only select repositories** | 点 **Select repositories** → 勾 **SkillsBin**（你截图里已经选对了） | ✅ |

> 选项下面那行小字 "**Also includes public repositories (read-only)**" 的意思：除了你勾的仓库，**所有公开仓库自动附带只读权限** —— 采集器读别人的 skill 仓库靠的就是它，**不需要再单独勾**。

**Permissions**（点 **`+ Add permissions`**，在下拉里逐个加这 **5 项**，每项选 **Read and write** —— 下拉里默认是 Read-only，注意改）：

| 要加的 5 项 | 级别 | 为什么需要 |
|---|---|---|
| **Contents** | Read and write | 推代码与数据；读公开仓库元数据 / 文件树 / 文件正文 |
| **Pull requests** | Read and write | 审核链路建 PR、读 PR、合并 |
| **Workflows** | Read and write | 推送 `.github/workflows/*.yml` —— **不勾会被 GitHub 直接拒绝推送**（GetHub 踩过） |
| **Administration** | Read and write | 设 Actions 的 Workflow permissions = write 与允许创建 PR（即上面 §2.3 的两个开关） |
| **Secrets** | Read and write | 写仓库 Secrets（`CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` / `GH_PAT`），免得你手工粘贴三遍 |

- **`Metadata` 不用加**，GitHub 自动带上。
- **Account 页签保持 0**，本站用不到账号级权限。

**备选（若你想省事）**：用 **classic PAT**，只需勾 `repo` + `workflow` 两个 scope，同样覆盖以上全部能力。代价是 classic 令牌是账号级、粒度粗，且 GitHub 在往 fine-grained 迁。**两者我都支持，你选一个填进 `GITHUB_TOKEN` 即可。**

**这个令牌是采集链路的必需品，不是可选项** —— GitHub **代码搜索 API 匿名不可用**（`GET /search/code` 必须带 token），而它是 skill 生态里唯一能穷举 `SKILL.md` 的手段。

### 2.5 新 Cloudflare 账号 + API Token（4 项权限）

**账号**：dash.cloudflare.com 注册 → 登录后右侧栏 **Overview** 页右下角那串 32 位 ID 就是 `CLOUDFLARE_ACCOUNT_ID`。

**令牌**：My Profile → **API Tokens** → Create Token → **Create Custom Token**

| Permissions | 级别 | 用途 |
|---|---|---|
| Account · **Cloudflare Pages** | Edit | wrangler 直传发布、建 Pages 项目、绑自定义域 |
| Account · **Account Settings** | Read | 读 Account ID 做校验 |
| Zone · **Zone** | Read | 列 zone / 读 zone ID |
| Zone · **DNS** | Edit | 绑自定义域所需的 DNS 记录、迁移时导入记录 |
| Zone · **Zone Settings** | Edit | *（可选）* 顺手开 Always Use HTTPS 与 HSTS |

- **Account Resources**：Include · 你的新账号
- **Zone Resources**：Include · Specific zone · **`skillsbin.cn`**

> 为什么不用 Cloudflare 面板的「连接 Git」：必须在面板授权 `Cloudflare Workers and Pages GitHub App`（OAuth，API 代不了），会报错码 **8000011**。所以走 **Actions + wrangler 直传**（GetHub 已验证）。

### 2.6 把 `skillsbin.cn` 的 zone 迁到新账号（A 方案）

**前提事实（文档 §10.6）**：`skillsbin.cn` 与 `skillskit.cn` 目前都已解析到 Cloudflare 节点（`172.67.x` / `104.21.x`），说明**已经进了某个 CF 账号**（大概率是你现在的账号）。

| 情况 | 处置 | 代价 |
|---|---|---|
| **A. zone 在旧账号 → 迁移到新账号** | 导出记录 → 新账号添加 zone → 导入记录 → 到注册商改 NS → 再绑 Pages | 一次维护窗口；**最干净，长期推荐**（你已选这条） |
| B. zone 留旧账号 → CNAME 跨账号指 Pages | 当天可上线；但 DNS 控制权留在旧账号，两站耦合，zone 级缓存规则由旧账号生效 | |
| C. 尚未加入任何账号 | 直接在新账号添加，最省事 | |

**A 方案四步**

1. **导出**（旧账号）：`skillsbin.cn` → **DNS** 标签页 → 右侧 **Export** 按钮 → 下载记录文件。
   - 你可以自己下载后放到项目根目录 `secrets/` 下（已 gitignore），我读文件导入；
   - 或者在 `.deploy.env` 里填 `CF_OLD_API_TOKEN`（只读权限 `Zone·Zone·Read` + `Zone·DNS·Read`），我用 API 导出。
   - 提示：CF 的导出是 BIND 格式，新账号的 Import 直接吃同一种格式。
2. **添加 zone**（新账号）：Add a site → 输入 `skillsbin.cn` → 选 Free 计划。
   - 添加后新账号会**分配一组它自己的 NS**，页面上会显示两个 NS 值 —— 把它们复制下来，下一步要用。
3. **导入记录**（新账号）：DNS → **Import** → 上传第 1 步的导出文件。
   - 此步我可以代做（需 `Zone·DNS·Edit`，已要）。
4. **改 NS**（⚠️ **只能你人工做**）：到 `.cn` 域名的注册商后台，把域名的 NS 记录改成第 2 步拿到的两个新 NS 值。
   - 生效窗口 **1~24 小时**。生效后 CF 会自动签发证书。
   - 改完把 NS 值发我，我 `dig NS skillsbin.cn` 帮你确认生效。

> **顺序建议**：现在站点还没上线，迁 zone 期间没有解析真空。**先迁 zone，再绑 Pages**，一步到位。
> `skillskit.cn` 先不动，等主站上线后再定「做子品牌」还是「301 到主站防流量误入」。

### 2.7 邮箱 `hi@skillsbin.cn`

只用在两个地方：**提交页的邮件兜底**（走 public 仓库后基本用不到）和**「要求下架」入口**。

- 已开通 → `.deploy.env` 里保持 `SITE_MAIL=hi@skillsbin.cn`。
- 没开通 → 先填一个你现在能收信的邮箱，上线后再换，不影响开发。

## 4. 附录 A：站点运行会用到的 GitHub 接口全集

开发文档 §6.1 的七类数据源。**这些是程序自己调的，你不需要申请什么** —— 列在这里是为了让你知道那个 PAT 会被用在哪。

| 代号 | 接口 | 用途 | 配额成本 |
|---|---|---|---|
| **S1** | `GET /repos/:owner/:repo` | 仓库描述 / 星标 / 许可 / topics / 最近 push 时间 | 1 次 core |
| **S2** | `GET /repos/:owner/:repo/git/trees/:sha?recursive=1` | 在文件树里定位 `SKILL.md` 路径 | 1 次 core |
| **S3** | `raw.githubusercontent.com/:owner/:repo/:commit/:path` | 取 frontmatter 与正文 | **0 —— 不计 API 配额**（这是把每仓库成本从 3 次降到 2 次的关键） |
| **S4** | `GET /search/code?q=filename:SKILL.md` | 穷举发现新仓库 | 搜索桶 **10 次/分钟**，**必须带 token**，每轮限用 10 次 |
| **S5** | `GET /search/repositories?q=topic:claude-skills stars:>150` | 关键词发现新仓库 | 搜索桶 30 次/分钟 |
| **S6** | `crawler/sources/*.json`（awesome 清单等） | 不依赖 API 的种子补充 | 0 |
| **S7** | `submissions/*.json`（人工投稿） | 人工审核通过后收录 | 0 |

**写接口（审核链路用）**

| 接口 | 用途 |
|---|---|
| `PUT /repos/:owner/:repo/contents/:path` | 写 `submissions/`、追加 `crawler/config.json` 的 watchlist |
| `POST /repos/:owner/:repo/pulls` | 自动发现候选 → 开审核 PR |
| `PUT /repos/:owner/:repo/pulls/:number/merge` | 审核通过 → 合并 |
| `PUT /repos/:owner/:repo/actions/secrets/:name` | 写仓库 Secrets（libsodium `crypto_box_seal` 加密，**不能用 tweetnacl 手搓**，会被判 422） |
| `PUT /repos/:owner/:repo/actions/permissions/workflow` | 设 §2.3 的两个开关 |

**一轮的配额账**：1500 仓库 × 2 次 = 3000 次请求，`requestBudget` 设 4200（GitHub 上限 5000/h，留 800 余量），够用。
配额三护栏：`requestBudget 4200` / `reserveQuota 250`（剩 <250 立刻落盘退出，**绝不撞到 403 干等**）/ `refreshHours 20 > cron 12h`（保证每轮都有活干又不会重复采）。

## 6. 我拿到凭据后的前 6 步（让你知道下一步会发生什么）

1. 跑 `check-credentials.mjs` 自检，把结果表给你确认。
2. `git init` + 首次推送代码到 `SkillsBin`（**如果 §2.3 两个开关没设，我用 API 补设**）。
3. 建 Pages 项目 `skillsbin`，首次 `wrangler pages deploy`。

5. 迁 zone：导入 DNS 记录 → 给你 NS 值 → 你去注册商改 → 我 `dig` 复查 → 绑自定义域 + 开 HTTPS。
6. 小流量试采（`--limit 50`）确认解析率与配额，再放开 `sync.yml` 的 12h 定时。

## 7. 安全约定（不可越线）

- `.deploy.env` **永不入库**（已在 `.gitignore`）；仓库 Secrets 里的值只写一次，之后不再读取。
- **CF Pages 有「资产保留缓存」**：文件从部署里删掉后仍可能被公网访问约一周，**且无法手动清除** → 所以**任何密钥都不能进仓库**，这条与仓库可见性无关，始终生效。
- 泄密自检写进构建脚本：产物里出现 `crawler/`、`.github/`、`.deploy.env`、`.workbuddy/`、`.git`、`scripts/` 任一路径 → **直接 fail 发布**。
- 本机 git 若配了第三方镜像代理（`url.*.insteadOf`），推送私有内容要用显式令牌 URL：`https://x-access-token:$TOK@github.com/<owner>/<repo>.git`。
